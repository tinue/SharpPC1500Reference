## 1. What the SC-7852 is

The PC-1600 has **three** CPUs: two main CPUs and one sub-CPU (TRM §7.1):

| Device | Role | Equivalent to | Clock |
|---|---|---|---|
| **SC-7852** | Main CPU 1 — runs BASIC, the OS, and all native PC-1600 code | Z-80A | **3.58 MHz** |
| LH-5803 | Main CPU 2 — runs PC-1500-compatible LH-5801 code | LH-5801 | 1.3 MHz (2.6 MHz crystal ÷2) |
| LU-57813P | Sub-CPU — power management, RTC, key-wake, ON/BREAK | — | 307.2 kHz |

The SC-7852 is a **one-chip, 100-pin CMOS LSI developed specifically for the PC-1600**.
Per the internal block diagram (TRM §7.1.1(1)) it contains:

- a **Z-80A-equivalent CPU core**;
- a **clock generator (CGC)** driven by the 3.58 MHz crystal;
- a **memory-select circuit** (generates CS001 / CS123 / CS24 / RAM1 / RAM2 / RAM3 /
  LHS1–3 — the chip-selects the LR38041 gate array and memory PWB consume; see
  `PC-1600-Memory-Bank-Switching.md` Part 4);
- an **interrupt control circuit**;
- an **I/O port** block that is **LH-5810/LH-5811-compatible** (reachable at Z-80 I/O
  ports 10–1FH; *not* synchronised to φOS) — this drives the keyboard strobes, the
  buzzer, and the cassette output;
- an **LH-5803 interface** block (LH I/F) — bus hand-off, wait generation for the
  LH-5803, and the ME0/ME1 ↔ MREQ/IORQ signal multiplexing.

The core is "Z-80A-equivalent circuitry"; the extra silicon is what a plain Z-80A does
not have, exposed on terminals a Z-80A does not have (§4 below).

## 2. Clock and timing

### 2.1 Clock

- 3.58 MHz crystal across **XIN (pin 89) / XOUT (pin 88)**; buffered Z-80 clock out on
  **CLK (pin 86)**, stated as "3.58 MHz for the PC-1600".
- One T-state ≈ **1 / 3.58 MHz ≈ 279.3 ns**.
- φOS (pin 4, an input to the SC-7852 from the LH-5803 side) is the **1.3 MHz** LH-5803
  basic clock; the SC-7852 also derives the **217 kHz LCD clock (CK0, pin 56)** from it.
  φOS is *not* the Z-80 core clock — do not confuse the two.

### 2.2 Instruction timing = nominal Zilog Z-80A

The instruction tables in §10.4 give, for every instruction, **No. of bytes / No. of M
cycles / No. of T states**, and these values are the **standard Zilog Z-80A figures,
verbatim** (spot-checked across the load, exchange/block-transfer, 8-bit arithmetic,
jump, call/return and I/O groups: `LD r,r'` = 4T, `LD r,(HL)` = 7T, `LD r,(IX+d)` = 19T,
`LDIR` = 21T/16T, `INC (HL)` = 11T, `JP nn` = 10T, `JR e` = 12T, `DJNZ` = 13T/8T,
`CALL nn` = 17T, `RET` = 10T, `RETI` = 14T, `RST p` = 11T, `IN A,(n)` = 11T,
`INIR` = 21T/16T — all canonical). **No instruction carries a PC-1600-specific
opcode, byte count, flag effect, or nominal cycle count.**

### 2.3 The documented deviation — one automatic wait state

The one timing difference the manuals state is a footnote to the **I/O map** table in
TRM §7.1.1(3) / Systemhandbuch §7.1:

> *"Im Maschinenzyklus wird 1 WAIT automatisch eingefügt."*
> *("In the machine cycle, 1 WAIT is automatically inserted.")*

Interpretation is **not fully settled by the source**:

- It is printed directly beneath the I/O-map table, which argues for it meaning *the I/O
  read/write machine cycle* specifically — i.e. `IN`/`OUT` cycles get one wait beyond the
  Z-80A's own built-in I/O wait. That reading leaves memory-cycle timing at the nominal
  Z-80A values.
- Taken literally ("the machine cycle"), it would mean **one wait per M-cycle**, making
  every instruction's real duration `T_nominal + M_nominal` T-states (e.g. `LD r,r'`
  4 → 5, `LD A,(nn)` 13 → 17). This is the more aggressive reading and would materially
  slow the machine relative to a 3.58 MHz Z-80A.
- The independent emulator cross-reference (`README.md` — *Sources & validation*) models
  **no extra wait** — nominal Zilog cycle counts at ~3.5 MHz — but that is a choice made
  in the absence of a Sharp timing figure, not a confirmation.

**Open item for the emulation effort:** decide which reading the real hardware follows
(measure a tight loop's wall-clock rate on a real PC-1600, or find a Sharp timing
diagram). Until then, model nominal Zilog timing at 3.58 MHz and treat the wait as a
known unknown. See §12.

### 2.4 Additional waits on the LH-5803 side

Two SC-7852 outputs insert waits into **LH-5803** cycles (not Z-80 cycles), for accesses
to regions the gate array has to intercept:

- **LHWAIT (pin 3)** goes high — one cycle, to insert one wait — when the LH-5803
  accesses `**00H` or `8000H–FFFFH` of its ME1 space, or when the SC-7852 and LH-5803
  are both in HALT, or whenever the external WAIT input is high.
- **IOE (pin 42)** is asserted when the LH-5803 accesses `**00H–**0FH` or `8000H–0FFFH`
  of ME1; it sends a wait to the LH-5803 and is issued with a **half-cycle delay**.

These belong to the compatibility path; detail in `PC-1600-CPU-LH5803-Compat.md`.

## 3. Programmer's model

Identical to the Z-80 (TRM §10.4(2)). "The CPU registers consist of 208 bits of R/W
memory" arranged as:

### 3.1 Registers

| Group | Registers |
|---|---|
| Main register set | **A F**, **B C**, **D E**, **H L** (8-bit; pair as BC/DE/HL 16-bit) |
| Alternate register set | **A' F'**, **B' C'**, **D' E'**, **H' L'** (reached via `EX AF,AF'` and `EXX`) |
| Special | **I** (interrupt vector, high byte), **R** (memory-refresh, 7-bit), **IX**, **IY**, **SP**, **PC** |

Register-selection field encodings used in the opcode tables:

```
r / r'   000=B 001=C 010=D 011=E 100=H 101=L 111=A     (110 = (HL) where an operand slot allows it)
dd/ss    00=BC 01=DE 10=HL 11=SP
qq       00=BC 01=DE 10=HL 11=AF        (PUSH/POP)
pp       00=BC 01=DE 10=IX 11=SP        (with IX-prefixed ADD)
rr       00=BC 01=DE 10=IY 11=SP        (with IY-prefixed ADD)
ii       IX or IY (prefix DD / FD)
cc       000=NZ 001=Z 010=NC 011=C 100=PO 101=PE 110=P 111=M
d        signed 8-bit displacement for (IX+d)/(IY+d)
e        relative-jump displacement; the assembled byte is e-2
n / nn   8-bit / 16-bit immediate (nn stored low byte first — little-endian)
```

### 3.2 Flag register (F / F')

TRM §10.4(1). Bit layout:

```
 bit  7   6   5   4   3   2    1   0
      S   Z   X   H   X   P/V  N   C
```

| Flag | Name | Notes |
|---|---|---|
| **C** | Carry | set on ADD overflow / SUB borrow; rotate/shift bit sink & source; `SCF` sets, `CCF` complements; cleared by `AND`/`OR`/`XOR` |
| **N** | Add/Subtract | used only by `DAA`; 1 after a subtract, 0 after an add. Not directly testable. |
| **P/V** | Parity/Overflow | signed overflow after arithmetic (result outside −128…+127); parity after logical/rotate; also `LD A,I` / `LD A,R` copy IFF2 here; block instructions use it as BC≠0 |
| **H** | Half-carry | BCD support for `DAA`. Not directly testable. |
| **Z** | Zero | result == 0 |
| **S** | Sign | bit 7 of the result |
| bits 3, 5 | unused | documented "not used" (the undocumented Z-80 XF/YF behaviour is not described by Sharp — see §6.4) |

Testable by conditional `JP`/`JR`/`CALL`/`RET`: **C, Z, P/V, S** (as NZ/Z/NC/C/PO/PE/P/M).

### 3.3 Byte order

Little-endian, like any Z-80: 16-bit immediates and addresses are stored low byte first,
`(nn)` operands likewise. **Contrast the LH-5803**, which stores addresses high byte
first and inverts A15 as seen from the SC-7852 side (`PC-1600-CPU-LH5803-Compat.md`,
TRM §7.2).

## 4. Instruction set

**The SC-7852 executes the full standard Zilog Z-80A instruction set**, unmodified. §10.4
of the Systemhandbuch reproduces it in 13 groups; the mnemonics, operations, flag
columns, opcode bit-patterns and cycle counts are the canonical Zilog values. Use any
Zilog Z-80 CPU User Manual, `z80dasm`, or `sdcc`/`z88dk`'s Z-80 backend as the
authoritative per-opcode reference — nothing about the PC-1600 changes them.

### 4.1 The 13 groups (as the manual organises them)

| § | Group | Representative timings (nominal T-states) |
|---|---|---|
| (1) | Flags | — |
| (2) | Internal register structure | — |
| (3) | **8-bit load** | `LD r,r'` 4 · `LD r,n` 7 · `LD r,(HL)` 7 · `LD r,(IX+d)` 19 · `LD (HL),n` 10 · `LD A,(nn)` 13 · `LD A,I`/`LD A,R` 9 |
| (4) | **16-bit load** | `LD dd,nn` 10 · `LD IX,nn` 14 · `LD HL,(nn)` 16 · `LD dd,(nn)` 20 · `LD SP,HL` 6 · `PUSH qq` 11 · `PUSH IX` 15 · `POP qq` 10 |
| (5) | **Exchange, block transfer, search** | `EX DE,HL` 4 · `EX (SP),HL` 19 · `EX (SP),IX` 23 · `EXX` 4 · `LDI`/`LDD` 16 · `LDIR`/`LDDR` 21/16 · `CPI`/`CPD` 16 · `CPIR`/`CPDR` 21/16 |
| (6) | **General-purpose arithmetic & CPU control** | `DAA` 4 · `CPL` 4 · `NEG` 8 · `CCF`/`SCF` 4 · `NOP` 4 · `HALT` 4 · `DI`/`EI` 4 · `IM 0/1/2` 8 |
| (7) | **8-bit arithmetic & logic** | `ADD A,r` 4 · `ADD A,n` 7 · `ADD A,(HL)` 7 · `ADD A,(IX+d)` 19 · `INC r` 4 · `INC (HL)` 11 · `INC (IX+d)` 23 (same pattern for ADC/SUB/SBC/AND/OR/XOR/CP and DEC) |
| (8) | **16-bit arithmetic** | `ADD HL,ss` 11 · `ADC HL,ss` / `SBC HL,ss` 15 · `ADD IX,pp` 15 · `INC ss` 6 · `INC IX` 10 · `DEC ss` 6 |
| (9) | **Rotate & shift** | `RLCA`/`RRCA`/`RLA`/`RRA` 4 · `RLC r` etc. 8 · `RLC (HL)` 15 · `RLC (IX+d)` 23 · `RLD`/`RRD` 18 |
| (10) | **Bit set / reset / test** | `BIT b,r` 8 · `BIT b,(HL)` 12 · `BIT b,(IX+d)` 20 · `SET/RES b,r` 8 · `SET/RES b,(HL)` 15 · `SET/RES b,(IX+d)` 23 |
| (11) | **Jump** | `JP nn` 10 · `JP cc,nn` 10 · `JR e` 12 · `JR cc,e` 12/7 · `JP (HL)` 4 · `JP (IX)`/`JP (IY)` 8 · `DJNZ e` 13/8 |
| (12) | **Call & return** | `CALL nn` 17 · `CALL cc,nn` 17/10 · `RET` 10 · `RET cc` 11/5 · `RETI`/`RETN` 14 · `RST p` 11 |
| (13) | **Input / output** | `IN A,(n)` 11 · `IN r,(C)` 12 · `INI`/`IND` 16 · `INIR`/`INDR` 21/16 · `OUT (n),A` 11 · `OUT (C),r` 12 · `OUTI`/`OUTD` 16 · `OTIR`/`OTDR` 21/16 |

Notes carried in the manual's own tables:
- **Block I/O Z-flag (`①`)**: `INI/IND/OUTI/OUTD` set Z=1 iff `B−1 == 0`, else Z=0.
- **Block transfer/search P/V (`①`)**: P/V = 1 while `BC−1 ≠ 0`, else 0.
- `LD A,I` / `LD A,R`: P/V ← IFF2, N ← 0, H ← 0 (so an interrupt between the opcode and
  the flag test can corrupt the P/V reading — standard Z-80 erratum, applies here too).
- `RST p` target: `t` field 000→00H, 001→08H, … 111→38H.

### 4.2 Addressing modes

Standard Z-80: immediate, immediate extended, register, register indirect `(HL)/(BC)/
(DE)`, indexed `(IX+d)/(IY+d)`, extended `(nn)`, relative (`JR`/`DJNZ`), bit, page-zero
(`RST`), I/O port (`(n)` and `(C)`), implied.

### 4.3 Opcode prefixes

All four Z-80 prefixes are present and behave normally: **CB** (rotate/shift/bit), **ED**
(extended: block ops, `IN/OUT (C)`, `LD dd,(nn)`, `NEG`, `IM`, `RETI/RETN`, `RLD/RRD`,
`LD A,I/R`), **DD** (IX), **FD** (IY), **DD CB dd op** / **FD CB dd op** (indexed
bit/shift).

### 4.4 Undocumented / illegal opcodes

Sharp documents only the official instruction set. The behaviour of the well-known
undocumented Z-80 opcodes — IXH/IXL/IYH/IYL 8-bit halves, `SLL`, the `ED` no-ops,
flag bits 3/5 (XF/YF) after arithmetic, `BIT n,(IX+d)` flag quirks, `OUT (C),0` vs
`OUT (C),255` — is **not stated** for the SC-7852. The core is described only as "Z-80A
equivalent". Whether it matches NMOS Zilog, CMOS (Z84C00), or diverges is **unverified**.
For emulation, start from a standard NMOS Z-80 model and flag any code that depends on
undocumented behaviour for a real-hardware check. (The PC-1600 ROM disassembly project,
`PC-1600-ROM-Disassembly.md`, is the place such a dependency would first surface.)

## 5. Interrupts

### 5.1 Mode

The PC-1600 runs the Z-80 in **interrupt mode 2** (TRM §3.4.1(3)). `IM 2` and the IRQ
mask are put in the set state during the reset routine.

- **Vector**: high byte = `I` register; low byte = **I/O port 39H** (`IOW VCT`). The
  16-bit table entry is stored at **(routine entry address − 2)**, low byte then high
  byte. The system-reset routine's entry address is itself readable from `0003H`/`0004H`
  (low, high).
- **NMI** (pin, `NMI` / analog of Z-80 NMI): high input causes an interrupt; vector is
  the usual `0066H`. `RETN` returns (14T) and restores IFF1←IFF2.
- **INT/IRQ acknowledge**: standard Z-80 IM2 acknowledge cycle.

### 5.2 Cause and mask registers

Two I/O ports, **same bit layout**, both concerning the interrupt *causes* the SC-7852
aggregates onto its INT line:

| Port | Access | Meaning |
|---|---|---|
| **35H** (`IOW/IOR ZMSK`) | read/write | mask: bit=1 → that cause is **enabled**, bit=0 → disabled |
| **32H** (`IOR INT`) | read | pending: bit=1 → that cause has a request outstanding |

Bit assignment (LSB → MSB, from TRM §3.4.1(1)):

| Bit | Cause | Hardware source |
|---|---|---|
| 0 | Communication port received data | TC8576F UART → INT0 (pin 81) |
| 1 | Interrupt from a **PC-1600** peripheral device | INT1 (pin 82), active low |
| 2 | Interrupt from a **PC-1500** peripheral device | IRQ (pin 80) |
| 3 | Interrupt from the LH-5801/5803 side | — |
| 4 | 1/64-second timer | INT4 (pin 83), 1/64 s pulse from the sub-CPU; tied to PB5 |
| 5 | Key input | — |
| 6 | Interrupt from the sub-CPU | INT6 (pin 84); carries 0.5 s timer, low-battery, analog-in, CI, auto-power-off, RS-232C timeout, wakeup/alarm1/alarm2 |
| 7 | must always be 0 | — |

Firmware-level handlers (what the OS does per cause) are listed in TRM §3.4.1(2):
(a) comm-port RX → buffer + XON/XOFF; (b) PC-1600 peripheral → e.g. CE-1600P paper feed;
(c) PC-1500 peripheral → e.g. CE-150 paper feed; (d) 1/64 s timer → key scan + cursor
blink; (e) sub-CPU → 0.5 s-timer tasks (battery/analog/CI checks, auto-power-off, RS-232C
timeout), wakeup timer, alarm1/alarm2.

**Bit 4's exact waveform, confirmed (Systemhandbuch §7.3/§7.4, 2026-08-30):** the LU-57813P
sub-CPU's pin 27 (Z6) is described in the pinout table as *"1/64-second pulse of 50%
quality/duty was sent. Connected to the INT4 and PB5 inputs of the SC-7852"* — i.e. a
plain **free-running 50%-duty square wave**, generated continuously by the sub-CPU
independent of any CPU-switch/handoff state, not an edge-triggered event that needs an
explicit acknowledge/clear write to fall back to 0. §7.4 ("Tastatur") independently
confirms the same signal is what drives the 1/64 s keyboard-scan interrupt: *"Die Tasten
der Tastatur werden durch Unterbrechen des SC7852 jede 1/64 s gescannt durch den 64 Hz
Impuls, der durch das ZS Terminal der Sub-CPU LU57813P erzeugt wird"* ("the keyboard is
scanned by interrupting the SC-7852 every 1/64 s via the 64 Hz pulse generated by the
sub-CPU's Z6 terminal"). This resolves the "reconcile 32H/35H edge/level behaviour" open
item **for bit 4 specifically**: it's a level, oscillating at 64 Hz with 50% duty (~7.8 ms
high / ~7.8 ms low), readable directly on port 32H at any time — polling code does not
need to wait for a true Z-80 `INT`-acknowledge cycle to observe it toggle. Bits 0-3/5-7's
edge/level behaviour remains open (still needs TRM §3.4 proper, not this pinout table).

### 5.2a User interrupt-service hooks (TRM §3.4.1(4))

Five interrupts can be routed to a user handler by filling a work-area slot with the
handler's **bank number** and **address**:

| Interrupt | bank byte | address (L, H) | extra enable |
|---|---|---|---|
| 1/64 s timer | F0BCH | F0BDH–F0BEH | also set **MSB of F0B7H** |
| 0.5 s timer | F0BFH | F0C0H–F0C1H | also set **MSB of F0B5H** |
| Alarm 1 timer | F0C2H | F0C3H–F0C4H | — |
| Alarm 2 timer | F0C5H | F0C6H–F0C7H | — |
| Wakeup timer | F0C8H | F0C9H–F0CAH | — |

Bank byte: **b0** = the bank number; the service only runs when **b6 = b7 = 1** (the
"handler present" gate). Address is stored low byte then high byte.

Other §3.4.2 interrupt work: **F05EH** b0 = cursor on-state during blink, b1 = suppress
LCD-driver access inside an ISR; **F068H** cursor-blink counter; **F069H–F078H** save
area for the dot pattern under the cursor; **F07AH** (KEYWK2) b0 key-debounce, b2
KEYGET-executing (auto-power-off), b3 suppress keyboard-port access inside an ISR, b4
force-return from KEYGET.

### 5.3 RST vectors (TRM §5.13)

Some Z-80 `RST` slots are exposed to the user; each has a **3-byte slot in the system
work area** that holds `RET` when unused — write a `JP xxxx` there to hook it.

| RST | Target | Status |
|---|---|---|
| `RST 00H` | — | System reset |
| `RST 08H` | — | Reserved by Sharp |
| `RST 10H` | — | Reserved by Sharp |
| `RST 18H` | — | Reserved by Sharp — **inter-bank jump** (`BANKJP`; see `PC-1600-Memory-Bank-Switching.md` Part 6) |
| `RST 20H` | — | Reserved by Sharp — **inter-bank call** (`BANKCAL`; ibid.) |
| `RST 28H` | — | Reserved by Sharp |
| `RST 30H` | `JP F0D4H` | **Open to user** (3-byte JP slot at F0D4H) |
| `RST 38H` | `JP F0D7H` | **Open to user** (3-byte JP slot at F0D7H) — note this is also the IM1 vector location; the OS runs IM2, so `RST 38H` is free |

## 7. On-chip I/O and the internal control-register block

TRM §7.1.1(3). "Similar to the Z-80A, the SC-7852 has a 256-byte I/O space (00H–FFH)."

### 7.1 I/O map (range level)

| Range | Assignment |
|---|---|
| 00H–0FH | **Use prohibited** |
| 10H–1FH | LH-5810/LH-5811-compatible port, inside the SC-7852 (**not** synchronised to φOS) |
| 20H–27H | TC8576F UART select (IOSU#) |
| 28H–2FH | S2 (Slot 2) — KA1#/KA2# strobes |
| **30H–3FH** | **SC-7852 internal LSI control-register port** (see §7.2) |
| 40H–4FH | System reserve (E# strobe region 40H–5FH) |
| 50H–57H | HD61102 LCD column driver (IC2) |
| 58H–5BH | HD61102 LCD column driver (IC3) |
| 60H–6FH | S2 (Slot 2), second window (KA0#) |
| 78H–7FH | CE-1600F (floppy) |
| 80H–83H | CE-1600P (plotter/printer) |
| 84H–BFH | Reserved for future extension |

### 7.2 Internal control registers, 30H–3FH

Read and write at each port do **different** things (the manual lists an `IOR xxx` and an
`IOW xxx` name per address). The `#Rreg` column in the source cross-references the
LH-5803-side ME1 shadow address `#A03xH`.

| Port | Read (`IOR`) | Write (`IOW`) | Purpose |
|---|---|---|---|
| 30H | MOD | MOD | Module control |
| **31H** | MAP | MAP | **Primary bank-select register** — see `PC-1600-Memory-Bank-Switching.md` Part 2 |
| 32H | INT | PRI | Read = interrupt-cause register (§5.2); write = interrupt priority |
| 33H | P | CDF | Read = data returning from the LU57813P sub-CPU (via IORP#); write = CDF |
| 34H | LHMSK | LHMSK | LH-5803-side interrupt mask |
| 35H | ZMSK | ZMSK | **Z-80-side interrupt mask** (§5.2) |
| 36H | ADRS | CL1 | Read = address; write = CL1 |
| 37H | KB | CGC | Read = keyboard; write = CGC register (bit 4 gates CK0 / the LCD clock) |
| 38H | — | STP | **CPU-switch trigger** — `OUT (38H),A` in the Z-80→LH-5803 hand-off sequence (§5.14; `PC-1600-Memory-Bank-Switching.md` Part 9) |
| 39H | — | VCT | **IM2 interrupt-vector low byte** (§5.1) |
| 3AH | — | KA | "Not used" |
| 3BH | — | KS | "Not used" |
| 3CH | — | SLT | Slot control; **bit 6 remaps LHS1–3** (§6, pin 46–48) |
| 3DH | — | C/D | Hidden-ROM / extended-address latch (`PC-1600-Memory-Bank-Switching.md` Part 2); latched on C/D# rising edge; state also mirrored at system address F07DH |
| 3EH, 3FH | — | — | unused |

> **Warning (from the manual):** *"If wrong values are written to an I/O area between 30H
> and 3DH so that the defaults are not correct, the PC-1600 does not operate properly."*
> Emulators and ML programs must preserve the OS's expected contents of this block.

### 7.3 Machine-cycle wait

The "1 WAIT automatically inserted in the machine cycle" note (§2.3) is printed with this
I/O map — hence the reading that it is specifically about I/O-access cycles. Unresolved;
see §12.

## 8. Simulation / ICE mode

Pin **T (87)**: low = normal. High = the Z-80 bus is tri-stated and an external Z-80 or
Z-80 in-circuit emulator drives the bus, connected through the **KIN0–KIN7** lines. This
is a hardware development hook, not used in normal operation.

## 9. Dual-CPU hand-off (summary)

Only one main CPU runs at a time; **ELH# (pin 77)** indicates which (low = LH-5803, high
= Z-80). A system reset drives ELH# high and the Z-80 runs first. The two CPUs are wired
to the same bus; the idle one is floated (TRM §7.1.4).

Bus-signal correspondence across the shared bus:

| SC-7852 pin | Z-80 meaning | LH-5803 meaning |
|---|---|---|
| A15–A0 | A15–A0 | A15–A0 |
| DB7–DB0 | D7–D0 | D7–D0 |
| MREQ (pin 35) | opposite polarity of Z-80 `MREQ#` | ME0 |
| IORQ (pin 34) | opposite polarity of Z-80 `IORQ#` | ME1 |
| RD# (pin 36) | RD# | OD |
| WR# (pin 9) | WR# | R/W |

**Hand-off:**

- Z-80 → LH-5803: `OUT (38H),A` (A irrelevant), then `HALT`. (The `11H → I/O 37H` write
  the OS also does first is a power-control step, not part of the switch itself —
  `PCTRL#`, pin 85.)
- LH-5803 → Z-80: `STA #A038H` — the LH-5803-side alias of I/O 38H (LH-5803 I/O 30–3FH
  shadow Z-80 I/O 30–3FH as `#A030H`–`#A03FH`, §7.2).

The OS wrapper for a call is `CALLH` at **01C6H** (parameters at F002H / F005H–F00BH /
F00CH / F00EH). Full mechanism, register block, and `XCALL`/`XPEEK`/`XPOKE` in
`PC-1600-CPU-LH5803-Compat.md`, `PC-1600-Machine-Overview.md` §3, and
`PC-1600-Memory-Bank-Switching.md` Part 8.

## 10. Reset state

- **RSTIN#** held low 30 ms by the sub-CPU on power-on / ACL / RESET.
- Standard Z-80 reset: `PC ← 0000H`, `I ← 00H`, `R ← 00H`, `IFF1 = IFF2 = 0`
  (interrupts disabled), `IM 0`. The PC-1600 reset **routine** then selects `IM 2`, sets
  the IRQ mask, and establishes the initial bank configuration (the gate array forces
  A16A high / A15A low / A14A high at reset — `PC-1600-Memory-Bank-Switching.md` Part 3).
- Reset cause is recorded by firmware at system address **F1ABH**
  (`PC-1600-Memory-Bank-Switching.md` Part 6).

## 11. Deviations from a stock Zilog Z-80A — summary

| Aspect | Stock Z-80A | PC-1600 SC-7852 |
|---|---|---|
| Instruction set, opcodes, byte counts, flag effects | Zilog standard | **Identical** (§10.4 is the Zilog set verbatim) |
| Nominal M-cycle / T-state counts | Zilog standard | **Identical** in the tables |
| **Effective cycle timing** | as published | **+1 automatic wait "in the machine cycle"** (TRM §7.1.1(3)); scope (I/O-cycle only vs. every M-cycle) unresolved; commonly modelled as none |
| Package | 40-pin DIP | **100-pin LSI**; extra terminals for bank select, chip selects, LH-5803 interface, I/O strobes, interrupt fan-in, power control, ICE mode |
| Clock | external | on-chip **CGC**, 3.58 MHz crystal, `CLK` buffered out |
| I/O ports 10–1FH | free | **on-chip LH-5810/5811-compatible port** (keyboard/buzzer/cassette), not φOS-synced |
| I/O ports 30–3FH | free | **on-chip control-register block** (bank register, interrupt mask/cause, CPU-switch trigger, IM2 vector latch, hidden-ROM latch, …) — corrupting it hangs the machine |
| Second bus master | none | shares the bus with the **LH-5803**; `ELH#` arbitrates; extra WAIT paths (LHWAIT, IOE) into LH-5803 cycles |
| Interrupts | INT/NMI pins, mode 0/1/2 | fixed **mode 2**; 7-source cause/mask aggregated in ports 32H/35H; vector low byte from port 39H |
| `RST` slots | all 8 to page-0 | 00H–28H reserved by Sharp (18H/20H = inter-bank call/jump); 30H/38H user hooks via 3-byte JP slots at F0D4H/F0D7H |
| Undocumented opcodes / XF-YF flags | NMOS-defined | **not documented by Sharp**; unverified |
| Refresh | DRAM refresh via R | R present; internal memory is static; RFSH pin also relays an LH-5803 signal |

## 12. Open questions

1. **Wait-state scope.** Does "1 WAIT automatically inserted in the machine cycle" mean
   every M-cycle, or only I/O machine cycles? Resolve by measuring a known loop's real
   execution rate on hardware, or from a Sharp bus-timing diagram. This directly sets the
   emulator's cycle model.
2. **Undocumented opcodes / flag bits 3 & 5** — match NMOS Zilog, CMOS Z84C00, or
   neither?
3. **Pins 91–94** were not on the transcribed scan pages — complete the terminal table
   from the English TRM or the Service Manual.
4. **`IN r,(C)` / `OUT (C),0`** behaviour and the exact A8–A15 contents during I/O
   cycles (the manual says `B → A8–A15` for `IN r,(C)`; confirm for the block-I/O
   variants and for `IN A,(n)` where it says `Acc → A8–A15`).
5. **Interrupt-cause bit 3 ("from LH-5801")** and bit 5 ("key input") — exact trigger
   conditions and how they interact with the sub-CPU path (bit 6).
6. Whether any **CB/ED/DD/FD** edge cases (e.g. `DD`/`FD` on a non-indexed opcode acting
   as a NOP-prefix) behave as on Zilog silicon.

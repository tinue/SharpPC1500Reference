# PC-1600 TC8576F / TC8576AF CPC — Register-Level Reference

The PC-1600's one serial engine and its link to the LU-57813P sub-CPU are the same chip:
the Toshiba **TC8576AF** *CPC* (Combination Peripheral Controller), which the TRM calls
**TC8576F**. It combines an RS-232C async receiver/transmitter (ART), a 12-bit baud-rate
generator, and a Centronics-style parallel port. This document is the chip-level
programming model, the PC-1600 wiring, and how the PC-1600 ROM programs the chip.

**Sources.**
- Toshiba, *TC8576AF, TC8577AP, TC8578AP Technical Data* (1987 data book, pp.159–196),
  cited as "DS §n". Local scan:

## 1. The chip family

| Device | Package | Parallel port |
|---|---|---|
| **TC8576AF** | 44-pin mini flat package | direction set by the `CDS` pin |
| TC8577AP | 40-pin DIP | output only (`CDS` tied to GND) |
| TC8578AP | 40-pin DIP | input only (`CDS` tied to VCC) |

The PC-1600 uses the TC8576AF. Its parallel port runs in **output mode** (`CDS` = 0): the
Z-80 writes a byte, the CPC drives it onto `/DATA1–8` and strobes `DSTB`. That port
carries sub-CPU commands, not printer data (§8).

Feature summary (DS §2): 8-bit CPU bus; ART with 5–8 data bits, 1 or 2 stop bits,
none/odd/even parity, false-start-bit rejection, automatic break detection, full double
buffering, and parity/overrun/framing error detection; baud generator with a 4-bit
prescaler and a 12-bit divider, 50–375 000 baud in principle (DS §1); single +5 V
CMOS; Schmitt-trigger I/O; `XCLK` up to 10 MHz.

## 3. Bus interface and port map

The CPC decodes `A1`, `A0`, `/RD` and `/WR` (DS §3.2 data-bus-mode table). In the PC-1600
`A1`/`A0` are address bits 1/0 and `/CS` covers 20H–27H, so:

| Port | A1 A0 | Read | Write |
|---|---|---|---|
| **20H** | 0 0 | serial input data (receive buffer) | serial output data (transmit buffer) |
| **21H** | 0 1 | parallel input data | parallel output data → `/DATA1–8`, starts a DSTB cycle |
| **22H** | 1 0 | **serial status** | **parameter register** (whichever PRn the address register points at) |
| **23H** | 1 1 | **parallel status** | **command / parameter address** (bits 7–6 decide which, §4) |

24H–27H mirror 20H–23H (incomplete decode, `PC-1600-IO-Ports.md` §3). With `/CS` high,
or with both `/RD` and `/WR` high, the data bus is Hi-Z.

Toshiba's own example program (DS §8.2) uses the same layout at base C0H
(`SDATA`=+0, `PDATA`=+1, `SSTUS`/`PARAS`=+2, `PSTUS`/`SPCON`=+3) with a Z-80. The PC-1600 is
the same arrangement at base 20H.

### 4.1 Writes to port 23H (DS §4.1)

| D7 D6 | Target |
|---|---|
| 0 x | **serial command register**: D6–D0 are the command |
| 1 0 | **parallel command register**: D5–D0 are the command |
| 1 1 | **parameter address set**: D2–D0 select PR0–PR7; **D5 = 1 holds the CPC in system reset** |

### 4.2 Parameter registers (DS §4.2)

Programming one parameter takes two writes: the address to 23H (`C0H + n`, D5 = 0), then
the value to 22H. Nothing in the data sheet says the address auto-increments. Toshiba's
init loop and the PC-1600 ROM both rewrite the address before every value
(`OUT (23H)` / `OUT (22H)` pairs), so emulate the parameter address as a plain latch.

## 5. Clocking and baud rate

### 5.1 Prescaler (PR7, DS §4.3)

`XCLK` passes through a 4-bit prescaler to become `SYS_CLK`, which times everything
inside the chip: the baud generator, the DSTB/ACK/PRIME pulse widths, and write
recovery.

| K = PR7 & 0FH | f(SYS_CLK) | duty |
|---|---|---|
| 0 | f(XCLK) / 16 | 1/16 |
| 1 | f(XCLK) | as XCLK |
| 2–15 | f(XCLK) / K | 1/K |

### 5.2 Baud-rate generator (PR1:PR0, DS §4.4)

B is the 12-bit value `PR1[3:0]:PR0`.

| B | Baud8x |
|---|---|
| 0 | f(SYS_CLK) / 4096 |
| 1 | stopped (no output) |
| 2–4095 | f(SYS_CLK) / B |

The ART samples at 8× the bit rate, so **baud = f(SYS_CLK) / (8 · B)**. The dividing
counter reloads only when a new divisor is written. A CPC reset does not stop the
prescaler or the baud generator (DS §4.5).

### 5.3 PC-1600 values

- **XCLK = 1 228 800 Hz** (`CL2`, passed through the gate array as `CLK1`).
- **PR7 = 02H** from the boot init (§9.1), so **SYS_CLK = 614 400 Hz** and
  **tSYS = 1.628 µs**.
- So **baud = 76 800 / B**, which is exactly the "divisor = 76800 / baud rate" rule the
  TRM gives for the CWCOM parameter block (`PC-1600-Serial-Commands.md` Part 2). The two
  sources confirm each other. The same 614 400 Hz column appears in DS Table 4.4 for an
  8 MHz XCLK with prescaler 13.

| Baud | B | Baud | B |
|---|---|---|---|
| 50 | 1536 | 1200 | 64 (ROM default) |
| 75 | 1024 | 2400 | 32 |
| 110 | 698 (−0.03 %) | 4800 | 16 |
| 150 | 512 | 9600 | 8 |
| 300 | 256 | 19200 | 4 |
| 600 | 128 | 38400 | 2 |

38 400 baud (B = 2) is the fastest rate available at this SYS_CLK. That matches the
"50–38400" range BASIC `SETCOM` accepts. The minimum Baud8x period is 320 ns (DS §9.3),
far below anything the PC-1600 can reach.

## 6. Serial channel (DS §5)

### 6.1 Serial mode — PR5 (DS §5.3)

| Bit | Name | Meaning |
|---|---|---|
| 7 | RxINTM | 1 = mask the receive-character (and break) interrupt |
| 6 | ERINTM | 1 = mask the receive-error interrupt |
| 5 | EP | parity: 0 = odd, 1 = even |
| 4 | PEN | 1 = parity enabled |
| 3–2 | NL1:NL0 | data bits: 00 = 5, 01 = 6, 10 = 7, 11 = 8 |
| 1 | TxINTM | 1 = mask the TxRDY interrupt (it also changes what TxRDY means, §6.3) |
| 0 | S0 | stop bits: 0 = 1, 1 = 2 |

Bits 0 and 2–5 are laid out exactly like the PC-1600 CWCOM/`SETCOM` parameter byte. The
ROM uses the stored byte directly (§9.2).

### 6.2 Serial command (port 23H write, D7 = 0; DS §5.4)

| Bit | Name | Effect |
|---|---|---|
| 7 | 0 | selects the serial command register |
| 6 | — | reserved |
| 5 | RTS | 1 → `/RTS` = 0 |
| 4 | ERS | 1 → clear PE, OE, FE, RBRK |
| 3 | SBRK | 1 → force TXD low (send break) |
| 2 | RxEN | receiver enable |
| 1 | DTR | 1 → `/DTR` = 0 |
| 0 | TxEN | transmitter enable |

### 6.3 Serial status (port 22H read; DS §5.5)

| Bit | Name | Meaning |
|---|---|---|
| 7 | DSR | inverse of the `/DSR` pin |
| 6 | RBRK | break detected |
| 5 | FE | framing error (receiver checks only the first stop bit) |
| 4 | OE | overrun: an unread character was overwritten |
| 3 | PE | parity error |
| 2 | TxEMP | transmit buffer empty **and** the shifter idle |
| 1 | RxRDY | a received character is waiting; cleared when the CPU reads port 20H |
| 0 | TxRDY | TxINTM = 1: transmit buffer empty. TxINTM = 0: buffer empty · `/CTS` = 0 · TxEN = 1, the same condition as the Tx interrupt |

Error flags stay set until an ERS command. Errors do not stop the receiver (DS §5.8).

### 6.4 Transmit / receive behaviour (DS §5.1, §5.6–§5.8)

- **Frame:** idle high → start bit (low) → data LSB first → optional parity → 1 or 2 stop
  bits. Unused high data bits of a received character read as 0.
- **Transmit:** a write to 20H fills the transmit buffer. On each Baud8x edge the CPC
  checks TxEN = 1 **and** `/CTS` = 0 **and** transmitter idle before it starts the
  character. A second byte can be buffered while the first shifts out (double
  buffering). If TxEN or CTS drops mid-character, that character still finishes
  completely. A buffered byte then waits until both are true again. TxEMP rises after
  the last stop bit.
- **Receive:** a falling edge on RXD, then **four consecutive low samples** at Baud8x,
  makes a valid start bit. Otherwise it is a false start and is ignored. Bits are then
  sampled mid-cell. RXD held low for **two character times** sets RBRK.
- **RXD initialisation circuit:** after reset, and again after every break, the
  receiver will not look for a start bit until RXD has been seen high (two consecutive
  high samples after reset, one after a break). This stops a floating or unconnected
  line from reading as a break or as a spurious `00H`.

### 6.5 Serial interrupt equations (DS §5.9)

```
Tx int = TxEN · (/CTS = 0) · TxBufferEmpty · (TxINTM = 0)          (= TxRDY when TxINTM = 0)
Rx int = RxEN · [ (RxINTM = 0) · (RxRDY + RBRK) + (ERINTM = 0) · (FE + OE + PE) ]
INT    = Tx int + Rx int + parallel IntF                            (active high)
```

## 7. Reset and initialisation (DS §4.5)

The CPC resets while `/RESET` is low, and also from a write of parameter address with
D5 = 1 (e.g. `E0H`). That sets an internal system-reset flip-flop, which stays set until
a parameter-address write with D5 = 0. Toshiba recommends holding the chip in this state
during power-up and while loading all the parameters.

State after reset:

| Register / block | Reset value |
|---|---|
| Serial status | DSR = pin, RBRK/FE/OE/PE = 0, TxEMP = 1, RxRDY = 0, TxRDY = (per TxINTM) |
| Serial command | RTS = ERS = SBRK = RxEN = DTR = TxEN = 0 → `/RTS` = `/DTR` = 1 |
| Parallel command | IM1 = IM2 = 1 (both parallel interrupt factors masked), S = 0 |
| Parallel status (output mode) | IntF = 0, XBUSY = 0, PRIM = 0; BUSY/P5V/PE/SLCT/FAULT follow their pins |
| Prescaler + baud generator | keep running; **not** reset |
| DSTB/ACK/PRIME timing circuits | reset; PR2–PR4 **values kept** |
| TXD | forced high; any character in progress is aborted |
| Receiver | RxEN = 0, all flags cleared |

Parameter registers PR0–PR7 have no documented reset value: software must load all of
them.

## 8. Parallel port — output mode (CDS = 0; DS §6)

This is the mode the PC-1600 uses. In the PC-1600 the "printer" on the other end is the
**LU-57813P sub-CPU**.

### 8.1 Data and DSTB

A write to port 21H latches the byte and drives it **inverted** onto `/DATA1–8`. After
`Td` the CPC raises DSTB for `Tw`:

```
Td = tSYS × (PR2 + 2 + x)      x = 0…1 (synchronisation to SYS_CLK)
Tw = tSYS × (PR3 + 1)
```

**XBUSY** (parallel status D6) goes to 1 on the rising edge of `/WR` and clears on the
rising edge of the external **ACK**. It covers the gap before the device raises its own
BUSY. The ROM polls it to wait for the sub-CPU's acknowledge (§9.4).

### 8.2 Parallel status (port 23H read, output mode; DS §6.3)

| Bit | Meaning |
|---|---|
| 7 | IntF — a parallel interrupt factor is pending |
| 6 | XBUSY flag |
| 5 | BUSY — inverse of the `/BUSY` pin |
| 4 | PRIM — current level of the PRIME output |
| 3 | P5V — `/P5V` input (inverted) |
| 2 | PE — `/PE` input (inverted) |
| 1 | SLCT — `/SLCT` input (inverted) |
| 0 | FAULT — FAULT input (not inverted) |

### 8.3 Parallel command (port 23H write, D7:D6 = 10; DS §6.4)

| Bits | Meaning |
|---|---|
| D5 IM1 | 1 = mask interrupt factor 1 (handshake). While set, the INTP0/INTP1 flags are held reset. |
| D4 IM2 | 1 = mask interrupt factor 2 (status-line changes) |
| D2–D0 | operation, below |

| S2 S1 S0 | No. | Operation |
|---|---|---|
| 000 | 0 | clear the FAULT detection flag |
| 001 | 1 | clear the SLCT detection flag |
| 010 | 2 | clear the PE detection flag |
| 011 | 3 | clear the P5V detection flag |
| 100 | 4 | PRIME **level on** (held high) |
| 101 | 5 | PRIME **one-shot**, width `tPRIME = tSYS × (PR4 + 2)`, then low |
| 110 | 6 | PRIME **level off**, and clear **all** flags, including XBUSY and the interrupt flags |
| 111 | 7 | no operation |

So with both factors masked (`IM1 = IM2 = 1` → `B0H` base) the useful command bytes are
`B4H` (PRIME on), `B5H` (PRIME pulse), `B6H` (PRIME off + flag reset) and `B7H` (NOP).

### 8.4 Parallel mode — PR6, and interrupt factors (DS §6.5, §6.6)

- **Factor 1 (handshake).** Two flags: **INTP0** is set on the falling edge of XBUSY,
  i.e. when ACK arrives. **INTP1** is set on the falling edge of BUSY. **PR6.PP0 = 1**
  routes INTP0 to INT and **PR6.PP1 = 1** routes INTP1. Both flags are cleared by
  IM1 = 1, by a write to the parallel data register, or by any parallel command.
- **Factor 2 (status lines).** Four detection flags, OR'd together: PE is set on the
  falling edge of `/PE`; FAULT, SLCT and P5V on the rising edge of FAULT, `/SLCT`, `/P5V`.
  Masked by IM2. Cleared individually (commands 0–3), all at once (command 6), or by reset.

The PC-1600 sets PR6 = 00H and IM1 = IM2 = 1, so **the parallel side never interrupts**.
The ROM polls it instead.

### 8.5 Parallel input mode (CDS = 1; DS §7) — not used in the PC-1600

The PC-1600 does not use input mode. In brief: an external DSTB sets BUSY (`/BUSY` pin
low) and latches `/DATA1–8` (inverted) on its rising edge. The trailing edge sets
**BUFFUL**. A CPU read of port 21H (PR6.PP1 = 1) or a dummy write (PP1 = 0) generates an
ACK pulse, `To = tSYS × (1 + x)`, `Tw = tSYS × (PR2 + 1)`, and releases BUSY on one of its
edges. PR6.PP0 chooses whether BUSY spans the ACK. In this mode FAULT, `/SLCT`, `/PE` and
`/P5V` become outputs driven from parallel-command D0–D3. D4 ("Busy on") drives BUSY
directly and D5 masks the BUFFUL interrupt.

## 9. How the PC-1600 ROM programs the CPC

### 9.1 Boot initialisation — P0-B0 `078CH`

Called twice from the reset path (`0334H`, `038FH`):

```
078C  LD   A,E0H        ; param address 0 + system reset bit → CPC held in reset
078E  OUT  (23H),A
0790  LD   BC,06C2H     ; B = 6 parameters, C = C2H (address PR2, reset bit clear)
0793  LD   HL,07A5H
0796  LD   A,C / OUT (23H),A    ; select PRn  (first one also releases reset)
0799  LD   A,(HL) / OUT (22H),A ; load it
079C  INC  C / INC HL / DJNZ 0796
07A0  LD   A,B6H        ; parallel cmd: IM1=IM2=1, op 6 = PRIME off + clear all flags
07A2  OUT  (23H),A
07A5  DB   0FH,1FH,01H,CEH,00H,02H   ; PR2…PR7
```

| Reg | Value | Meaning in the PC-1600 |
|---|---|---|
| PR2 | 0FH | DSTB delay 15 → `Td` = 17–18 tSYS = **27.7–29.3 µs** |
| PR3 | 1FH | DSTB width 31 (the maximum) → `Tw` = 32 tSYS = **52.1 µs** |
| PR4 | 01H | PRIME one-shot = 3 tSYS = **4.9 µs** |
| PR5 | CEH | 8 data bits, no parity, 1 stop; **all serial interrupts masked** |
| PR6 | 00H | no parallel interrupts |
| PR7 | 02H | prescaler ÷2 → SYS_CLK 614.4 kHz |

PR0/PR1 (baud) are not written here. They are loaded when a channel is opened (§9.2),
and the default COM1 block at P2-B6 `9F5AH` is `40H 00H CCH`: B = 64 = **1200 baud**,
8 bits, no parity, 1 stop.

The final `B6H` also drives **PRIME low**, which selects SIO. That matches the TRM's
"power-on and reset leave PRIM low (SIO)".

### 9.2 Channel parameters (CWCOM / SETCOM) — P2-B6 `A306H`

```
A306  LD A,C0H / OUT (23H),A / LD A,(HL) / OUT (22H),A     ; PR0 = divisor low
A30F  LD A,C1H / OUT (23H),A / LD A,(HL) / OUT (22H),A     ; PR1 = divisor high
A318  LD A,C5H / OUT (23H),A / LD A,(HL)                   ; PR5 ← parameter byte …
A31E  OR 02H / AND 3FH / OUT (22H),A                       ; … with TxINTM=1, RxINTM=ERINTM=0
```

The CWCOM parameter byte (stop / length / parity bits 0, 2–5) goes into PR5 almost
unchanged. The ROM forces **TxINTM = 1** (no transmit interrupt, TxRDY = plain
buffer-empty) and **clears RxINTM/ERINTM** (receive and error interrupts on, via
`INT0`). That discards CWCOM bits 6–7 (XON/XOFF, SI/SO), which the firmware handles in
software.

### 9.3 Serial command shadow — `F14FH`

The ROM never builds serial-command bytes from scratch. It keeps a shadow in **`F14FH`**,
whose bits 0–5 are the command register (b5 RTS, b3 SBRK, b1 DTR as listed in
`PC-1600-Work-Area-Map.md` §3.10, plus b2 RxEN, b0 TxEN). **Bit 7** is a firmware flag
and is masked off (`AND 7FH`) before every `OUT (23H)`, because D7 = 0 is what selects
the serial command register.

| Site | Byte sent | Purpose |
|---|---|---|
| P2-B6 `9FA9H` → `9FD4H` | `05H` | RxEN + TxEN, RTS/DTR off |
| P2-B6 `9F97H` → `9FD4H` | `27H` | RTS + RxEN + DTR + TxEN (Toshiba's own example uses the same value) |
| P2-B6 `A34CH` | shadow `| 08H`, later shadow | send break (SBRK), then restore |
| P2-B6 `A44CH` | shadow `| 10H`, then `& EFH` | ERS pulse: clear PE/OE/FE/RBRK |
| P1-B3 `6503H` | shadow `& DFH` | drop RTS (receive flow control) |

### 9.4 Sending a command to the sub-CPU — P2-B6 `A974H`

Every sub-CPU command goes through one routine:

1. Mask Z-80 interrupts (`OUT (35H),0`, `AA26H`). Run `AA33H`, which reads serial status
   and services any pending receive (`AND 7AH`: RBRK/FE/OE/PE/RxRDY). This keeps an
   incoming serial byte from being lost while the ROM waits on the sub-CPU.
2. **Wait for parallel-status D5 (BUSY) = 0.** That is the `/BUSY` pin high, the
   sub-CPU's `Z10` reporting ready.
3. **`CPL`** the command byte, then `OUT (21H),A` (`A9FBH`). The CPC drives `/DATA1–8`
   inverted, so the complement written to the register arrives at the sub-CPU's R00–R13
   as the true command byte. (`PC-1600-IO-Ports.md` §7.3 gives the register values, e.g.
   `4FH` for command `B0H`.) Depending on `F0B8H` bit 0 the write is paced to the 64 Hz
   PB5 edge first (IO-Ports §7.3).
4. **Wait for parallel-status D6 (XBUSY) = 0** (`A98CH`, 65 536-iteration timeout).
   XBUSY was set by the `/WR` and is cleared by the sub-CPU's ACK (`Z9`). This is the
   "Z9 pulse = done" step of TRM §7.1.5.
5. For a data-returning command, read the answer with `IN A,(33H)` (the LR38041 return
   buffer, not the CPC), e.g. `A9C2H` sends `6FH` and reads 33H.
6. Unmask interrupts (`AA2CH`).

The DSTB that reaches the sub-CPU's `KI` input comes from the chip automatically on the
port-21H write. The ROM never touches DSTB itself.

### 9.5 RS-232C control lines through the parallel status port *(ROM)*

The CPC's serial side has only one readable modem input (DSR, serial status D7), and the
ROM never reads it. Instead the firmware reads the RS-232C handshake inputs from the
**parallel status** register: in output mode FAULT, `/SLCT` and `/PE` are plain inputs
that the sub-CPU link does not need.

- **CRCTRL (IOCS 11H), P2-B6 `A388H`:** `IN A,(23H)`, `RLCA ×2`, `AND 1CH` moves
  FAULT/SLCT/PE to INSTAT bits 2/3/4 (CS/CD/DR·IR). Bit 5 (CI) comes from the sub-CPU,
  and bits 0/1 (ER/RS) come from the `F14FH` shadow. `XOR 3BH` then puts the result in
  INSTAT polarity.
- **Send gating (CESND), P2-B6 `A524H`, and receive gating, P1-B3 `640DH`:**
  `IN A,(23H) / XOR 01H / AND mask`. The mask in `F148H` (send) or `F14BH` (receive) is
  built from CESND/CERCV's `E` as `(E >> 2) XOR 07H` (P2-B6 `A36BH`), so bit 0 = CS,
  bit 1 = CD, bit 2 = DR.

From that mapping: **CS → FAULT (pin 29), CD → `/SLCT` (pin 32), DR → `/PE` (pin 44)**,
each reading "on" when the CPC pin is low. The main-board wiring diagram labels the
BX7269W's CD input "SLCT", which agrees. This is not confirmed against a full schematic.

### 9.6 PRIME as the RS-232C / SIO switch *(ROM)*

P2-B6 `A41EH` writes `B4H + c` to port 23H, where `c` is one bit of the requested
channel: **`B4H` = PRIME level on** (PRIM high → RS-232C) or **`B5H` = PRIME one-shot**,
which ends low (PRIM low → SIO). It then spins about 16 k iterations, presumably to let
`VDD` settle, and reloads the channel parameters (`JP A306H`). Before switching,
P2-B6 `9F9DH` waits for serial-status TxEMP.

Command 6 (`B6H`) would also drive PRIME low, but it clears every parallel flag,
including XBUSY. That is presumably why the runtime switch uses the one-shot, which
leaves the sub-CPU handshake alone. `B6H` is used only at boot.

### 9.7 Transmit and receive paths

- **Transmit a byte**, P2-B6 `A542H`: poll serial status D0 (TxRDY) and `OUT (20H),A`.
  `A52CH`/`A580H` poll D2 (TxEMP) where the whole frame must have left.
- **Receive**, P1-B3 `63FAH`: `IN (22H) AND 78H` checks for errors or break, then
  `IN (20H)`. XON (`11H`) / XOFF (`13H`) are recognised in software. The receive side
  sends XOFF with `OUT (20H),13H` (`64F6H`) and drops RTS through the command shadow.

## 11. Emulation checklist

1. Port 23H writes split three ways on D7:D6 (§4.1). Port 22H writes go to `PR[addr]`.
   The address latch does not auto-increment.
2. Baud = 76 800 / B at the PC-1600's PR7 = 2, and TXD/RXD bit time = 8·B·tSYS. For
   host-side serial bridging, only B matters.
3. Serial status: TxRDY meaning depends on TxINTM (the ROM sets TxINTM = 1 → plain
   buffer-empty). RxRDY clears on the 20H read. Errors are sticky until ERS.
4. `INT0` = Rx interrupt (RxEN · unmasked RxRDY/RBRK/errors). The Tx interrupt is off in
   the PC-1600 and the parallel side never interrupts.
5. Parallel: a write to 21H sets XBUSY, drives the inverted byte to the sub-CPU model,
   and fires DSTB → sub-CPU `KI`. Sub-CPU ACK clears XBUSY. Status D5 reflects sub-CPU
   ready/busy. The ROM spins on D5 before sending and on D6 after, so both must move.
6. Status bits 0–2 of port 23H carry RS-232C CS/CD/DR (pin-low = asserted, FAULT not
   inverted by the CPC, SLCT/PE inverted). Bit 4 reflects PRIME = PRIM, the port select.
7. Parallel commands `B4H`/`B5H`/`B6H` switch PRIM. `B6H` also clears XBUSY.

## 12. Open items and data-sheet errata

- **DSTB timing vs. TRM §7.1.5.** The TRM figure shows the KI pulse as ≈13 µs / 26 µs.
  Those numbers are exactly `Td`/`Tw` for the ROM's PR2/PR3 at **SYS_CLK = 1.2288 MHz
  (K = 1)**. The ROM sets K = 2, which gives 27.7 µs / 52.1 µs, and K = 2 is the value
  that makes the TRM's own "76800 / baud" divisor rule come out right. Either the figure
  predates the final prescaler choice or it is schematic. A logic-analyser capture of
  DSTB would settle it.
- **`/CTS` (pin 35) and `/DSR` (pin 34) wiring** in the PC-1600 is unknown. The ROM
  reads CS through FAULT, but the CPC's own `/CTS` still gates the transmitter in
  hardware (§6.4). It must be held low (or follow CS) for SIO transmission to work.
- **CI (INSTAT b5)** comes from the sub-CPU (IOCS 13H inside `A388H`), not from the CPC.
- Data-sheet slips (the reading used here is in brackets):
  - DS §4.1 gives the write condition as "`/CS=1,/WR=1,/RD=0`" [`/CS=0,/WR=0,/RD=1`].
  - DS §5.5 heading says A1=1,A0=0 but the text says "A1=0 and A0=0" [A1=1, A0=0,
    per the register table].
  - The DS §3.2 TxRDY description says "data *receive* buffer is empty" [transmit buffer].
  - In the DS §8.2(b) sample, the second baud write repeats `LD A,0C0H` and `LD A,L`
    [`0C1H`, `H`].
  - The DS Table 4.4 6 MHz / prescaler-1 column lists B = 6982 / 10240 / 5120 for
    110 / 75 / 150 baud. These do not fit the 12-bit divisor (max 4095), so those rates
    are unreachable at that SYS_CLK.
